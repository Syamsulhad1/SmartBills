## Bagian 1. Identitas dan Topik Proyek Aplikasi

**Nama Aplikasi:** SmartBills

**Deskripsi Singkat dan Tujuan:** SmartBills adalah aplikasi pencatatan keuangan pribadi yang memanfaatkan teknologi OCR dan AI Agent (LLM) untuk membaca foto struk belanja atau bukti transfer, lalu secara otomatis mengubahnya menjadi data transaksi terstruktur dan memperbarui saldo pengguna secara real-time. # Bagian 3. Hubungan dan Implementasi pada Topik Proyek

## 1. Penyederhanaan tugas sehari-hari

Rancangan aplikasi SmartBills dibuat untuk mempermudah pengguna dalam mencatat dan memantau kondisi keuangan sehari-hari. Permasalahan utama yang ingin diselesaikan adalah proses pencatatan pemasukan dan pengeluaran secara manual yang membutuhkan waktu serta berisiko menyebabkan kesalahan pencatatan. SmartBills menyederhanakan proses tersebut dengan menggunakan AI Agent yang dapat menganalisis foto struk belanja atau bukti transfer menggunakan OCR dan LLM, kemudian mengubahnya menjadi data transaksi terstruktur.

Pada proses tradisional, pengguna harus melihat struk, kemudian mengetik sendiri informasi seperti jenis transaksi, nominal, kategori, dan rincian barang ke aplikasi atau spreadsheet. Pada SmartBills, pengguna cukup memotret atau mengunggah foto bukti transaksi melalui aplikasi mobile. Gambar tersebut dikirimkan ke backend melalui REST API, kemudian diproses oleh Google Cloud Vision untuk mengambil teks dari gambar dan diteruskan ke Gemini sebagai LLM Agent untuk mengubah teks tersebut menjadi data transaksi dalam format JSON.

Setelah transaksi berhasil diproses dan divalidasi, sistem secara otomatis memperbarui saldo pengguna dan menyimpan riwayat transaksi pada database PostgreSQL. Saldo tersebut kemudian dapat ditampilkan kembali secara real-time pada aplikasi mobile maupun Web Dashboard. Dengan demikian, proses yang sebelumnya dilakukan secara manual, yaitu melihat bukti transaksi → mencatat transaksi → menghitung saldo → membuat rekap, disederhanakan menjadi proses foto/upload bukti → AI memproses → transaksi tersimpan → saldo diperbarui → data ditampilkan dalam bentuk analitik.

## 2. Penyimpanan file dan keamanan password

SmartBills memiliki kebutuhan penyimpanan file terutama untuk menyimpan foto bukti transaksi, seperti struk belanja, nota, atau bukti transfer. Dalam rancangan sistem, foto bukti transaksi dikirimkan melalui aplikasi mobile dan disimpan di server untuk digunakan sebagai bagian dari riwayat serta audit transaksi.

Agar mudah dipahami pengguna awam, struktur penyimpanan dapat dibuat berdasarkan akun pengguna, tahun, bulan, dan transaksi. Contohnya:

```text
SmartBills/
└── User/
    └── 2026/
        └── September/
            ├── 2026-09-20_Indomaret.jpg
            ├── 2026-09-21_Transfer.jpg
            └── 2026-09-22_Telkomsel.jpg
```

Namun, struktur tersebut sebaiknya tidak perlu ditampilkan sebagai struktur folder teknis kepada pengguna. Pada antarmuka SmartBills, pengguna cukup melihat menu seperti **Riwayat Transaksi → September 2026 → Detail Transaksi → Bukti Transaksi**. Dengan demikian, pengguna awam dapat menemukan bukti transaksi berdasarkan waktu dan transaksi tanpa harus memahami struktur penyimpanan server.

Untuk keamanan akun, SmartBills dalam rancangan menggunakan **JWT (JSON Web Token)** sebagai mekanisme autentikasi pada REST API. Setiap request API dilengkapi token JWT untuk memastikan request berasal dari pengguna yang telah terautentikasi.

Selain itu, saat pendaftaran akun, aplikasi dapat membantu pengguna membuat password yang kuat dengan memberikan aturan seperti penggunaan password yang cukup panjang serta kombinasi huruf, angka, dan simbol. Aplikasi juga dapat memberikan indikator kekuatan password dan menolak password yang mudah ditebak atau menggunakan informasi pribadi. Hal ini sesuai dengan Modul 2 yang membahas pentingnya password kuat dan menghindari penggunaan informasi pribadi atau pola yang mudah ditebak.

## 3. Search bar dan asset eksternal

Pada SmartBills, fitur pencarian dapat dirancang untuk membantu pengguna menemukan transaksi dengan cepat tanpa harus melihat seluruh riwayat transaksi. **Search bar** dapat ditempatkan pada halaman riwayat transaksi dan memungkinkan pengguna mencari berdasarkan informasi yang relevan, seperti **nama merchant, kategori transaksi, deskripsi, atau periode transaksi**.

Contohnya:

```text
┌─────────────────────────────────────┐
│ 🔍 Cari transaksi...                │
└─────────────────────────────────────┘
```

Pengguna dapat mengetik:

```text
Indomaret
```

kemudian sistem menampilkan transaksi yang berkaitan dengan Indomaret.

Fitur pencarian juga dapat dilengkapi filter:

```text
Cari transaksi
├── Kata kunci
├── Tanggal
├── Kategori
├── Income
└── Expense
```

Konsep ini sesuai dengan Modul 3 yang mengajarkan teknik mempersempit pencarian agar informasi yang ditemukan lebih relevan serta pentingnya mengevaluasi hasil pencarian.

Berdasarkan dokumen rancangan, SmartBills menggunakan beberapa **library, API, dan teknologi eksternal**, yaitu:

| Google Gemini 1.5 | LLM Agent untuk parsing dan kategorisasi transaksi | Mengikuti ketentuan layanan/API Google |
| React Native (Expo) | Pengembangan aplikasi mobile | Mengikuti lisensi proyek |

Laporan perancangan belum mencantumkan secara spesifik status lisensi masing-masing asset. Oleh karena itu, dalam implementasi nyata lisensi masing-masing library harus diperiksa pada dokumentasi atau repository resminya. Untuk gambar dan icon yang digunakan dalam UI, sumber dan lisensinya juga harus dicatat. Hal ini sesuai dengan Modul 3 yang menjelaskan bahwa konten internet memiliki copyright dan aturan penggunaan tertentu, termasuk Creative Commons dan public domain.

## 4. Etika digital dan penggunaan AI

SmartBills pada rancangan saat ini **tidak memiliki fitur interaksi sosial sebagai fitur inti**. Fitur utamanya adalah pencatatan transaksi, sinkronisasi saldo, analitik keuangan, dan penyimpanan bukti transaksi.

Namun, jika suatu saat SmartBills memiliki fitur sosial, misalnya berbagi laporan keuangan atau berdiskusi dengan pengguna lain, maka aplikasi perlu menerapkan aturan untuk mencegah komunikasi yang tidak pantas, penyalahgunaan data, trolling, maupun cyberbullying. Pengguna dapat diberikan fitur **report, block, dan pengaturan privasi**, serta sistem dapat membatasi konten atau komunikasi yang melanggar aturan.

Untuk fitur AI, SmartBills menggunakan **OCR Google Cloud Vision dan Gemini sebagai LLM Agent**. AI digunakan untuk mengekstrak teks dari bukti transaksi, menentukan jenis transaksi, nominal, kategori, serta rincian item.

Agar penggunaannya bertanggung jawab, hasil AI tidak seharusnya dianggap selalu benar. SmartBills sudah memiliki fitur **Manual Transaction Entry & Data Correction**, sehingga pengguna dapat memperbaiki hasil ekstraksi apabila AI salah membaca atau mengategorikan transaksi.

Pendekatan tersebut penting karena rancangan juga mengakui adanya keterbatasan AI, misalnya kualitas OCR dapat menurun ketika foto buram, pencahayaan rendah, atau struktur struk tidak standar.

Dengan demikian, AI pada SmartBills berfungsi sebagai **alat bantu otomatisasi**, sedangkan pengguna tetap memiliki kesempatan untuk memeriksa dan memperbaiki hasilnya. Hal ini juga sejalan dengan Modul 4 yang membahas perkembangan AI sekaligus risiko seperti bias dan pentingnya penggunaan teknologi secara bertanggung jawab.

## 5. PII, perlindungan data, dan risiko penipuan

Karena SmartBills merupakan aplikasi keuangan pribadi, data yang perlu dilindungi terutama adalah **data akun pengguna dan data transaksi keuangan**. Berdasarkan rancangan sistem, database menyimpan data pengguna dan transaksi, sedangkan sistem juga menyimpan foto bukti transaksi untuk kebutuhan audit.

PII yang dapat berkaitan dengan akun pengguna antara lain **identitas akun dan informasi autentikasi**, sedangkan data transaksi dapat berisi informasi seperti nominal pemasukan atau pengeluaran, kategori transaksi, rincian barang, serta foto bukti transaksi. Namun, laporan perancangan belum merinci field PII akun seperti nama lengkap, nomor telepon, atau alamat email, sehingga bagian tersebut sebaiknya hanya dicantumkan apabila memang nantinya dikumpulkan oleh sistem.

Perlindungan data dilakukan melalui beberapa mekanisme. Pertama, komunikasi antara aplikasi mobile/web dengan backend menggunakan **HTTPS melalui REST API**. Kedua, request API menggunakan **JWT** untuk autentikasi pengguna. Ketiga, data transaksi disimpan pada database terpusat PostgreSQL dan akses terhadap data harus dibatasi berdasarkan akun pengguna.

SmartBills juga perlu menerapkan prinsip **data minimization**, yaitu hanya mengumpulkan data yang memang diperlukan untuk menjalankan fitur aplikasi. Foto bukti transaksi juga harus diperlakukan sebagai data yang sensitif karena dapat mengandung informasi transaksi atau identitas pengguna.

Untuk mengurangi risiko penipuan siber, aplikasi dapat memberikan edukasi kepada pengguna mengenai **phishing, spear phishing, dan penipuan online**, misalnya dengan tidak meminta pengguna memberikan password atau token melalui pesan yang mencurigakan. Modul 5 menjelaskan bahwa phishing dapat dilakukan dengan menyamar sebagai pihak yang terpercaya untuk memperoleh informasi pribadi, sedangkan spear phishing dapat menargetkan korban tertentu menggunakan informasi yang sudah diketahui tentang korban.

Dengan demikian, keamanan SmartBills tidak hanya bergantung pada sistem, tetapi juga pada kesadaran pengguna dalam menjaga informasi akun dan mengenali upaya penipuan.

## 6. Pesan error dan troubleshooting

SmartBills perlu memberikan **pesan error yang jelas dan mudah dipahami**, bukan hanya menampilkan pesan teknis seperti:

```text
HTTP 500 Internal Server Error
```

Pengguna awam biasanya tidak mengetahui arti pesan tersebut. Oleh karena itu, pesan error harus menjelaskan **apa yang terjadi, kemungkinan penyebabnya, dan apa yang dapat dilakukan pengguna**.

Hal ini sesuai dengan Modul 6 yang membahas troubleshooting. Modul memberikan pendekatan bertahap untuk masalah perangkat dan konektivitas, seperti memeriksa koneksi, memastikan Wi-Fi aktif, memeriksa jenis file, membersihkan penyimpanan, dan melakukan restart jika diperlukan.

Contohnya, ketika pengguna gagal mengunggah foto struk karena koneksi internet:

> **Koneksi internet bermasalah**  
> Foto struk belum berhasil dikirim ke SmartBills.
>
> Silakan:
> 1. Periksa koneksi Wi-Fi atau data seluler.
> 2. Pastikan koneksi internet aktif.
> 3. Coba unggah foto kembali.
>
> **[Coba Lagi]**

Jika AI gagal membaca struk:

> **Bukti transaksi belum dapat dibaca**  
> SmartBills belum dapat membaca informasi dari foto tersebut. Pastikan foto tidak buram, pencahayaan cukup, dan seluruh bagian struk terlihat.
>
> **[Ambil Foto Ulang] [Input Manual]**

Pesan kedua sesuai dengan keterbatasan yang sudah dicantumkan pada rancangan SmartBills, yaitu kualitas gambar yang buruk, pencahayaan rendah, dan format struk yang tidak standar dapat menurunkan akurasi OCR. Sistem juga menyediakan **Manual Transaction Entry & Data Correction** sebagai alternatif ketika hasil AI tidak sesuai.

Contoh lainnya ketika server atau API tidak tersedia:

> **SmartBills sedang mengalami gangguan koneksi**  
> Data terbaru belum dapat dimuat dari server. Periksa koneksi internet dan coba kembali beberapa saat lagi.
>
> **[Coba Lagi]**

Dengan rancangan tersebut, pesan error tidak hanya memberi tahu pengguna bahwa terjadi kesalahan, tetapi juga **memberikan langkah troubleshooting sederhana** yang dapat dilakukan sendiri.

## Kesimpulan

Secara keseluruhan, penerapan konsep **Digital Awareness Modul 1–6** pada SmartBills dapat terlihat langsung dalam rancangan aplikasinya. Konsep digitalisasi diterapkan dengan mengubah pencatatan keuangan manual menjadi proses otomatis berbasis aplikasi dan AI. Konsep keamanan diterapkan melalui autentikasi JWT dan perlindungan data pengguna. Konsep pencarian diterapkan melalui search bar dan filter transaksi. Konsep etika digital diterapkan melalui penggunaan AI yang tetap memberikan kesempatan kepada pengguna untuk memeriksa dan memperbaiki hasilnya. Kesadaran terhadap PII diterapkan melalui perlindungan data akun, transaksi, dan bukti transaksi. Sementara itu, konsep troubleshooting diterapkan melalui pesan error yang menjelaskan masalah sekaligus memberikan langkah penyelesaian kepada pengguna.

Rancangan tersebut mendukung tujuan utama SmartBills untuk membuat pencatatan keuangan menjadi lebih **otomatis, praktis, terstruktur, dan mudah dipahami pengguna**.
